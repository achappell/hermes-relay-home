- (decision) Use ports-and-adapters with small functional cores; HTTP, SQLite, credentials, and time remain adapters.
- (decision) The Home service is the sole authority for household configuration revision and wake arbitration; clients cache only for presentation.
- (decision) Versioned JSON schemas and the v1 HTTP contract are the wire authority, independent of the eventual Python HTTP framework.
- (decision) Configuration replacement validates the complete candidate before one durable transaction; expected_revision prevents stale overwrite.
- (decision) Home admin credentials and device credentials are distinct and never enter snapshots, URLs, logs, diagnostics, prompts, transcripts, or audio.
- (decision) Wake arbitration uses a 250 ms window on the Home monotonic receive clock, acoustic proximity evidence, and positive per-Room priority with 1 highest.
- (decision) Malformed, late, revoked, unavailable, or unmapped claims fail closed; a failed winner does not promote a loser.
- (decision) No generic hermes-relay-core extraction, cloud backend, or client presentation belongs in the first Home service slice.
- (event) Architecture spine seed drafted from the existing Home boundary and v1 contract.
- (decision by coach) Adopt the Home enrollment and revocation boundary: a short-lived single-use code creates a pending request, trusted control-plane approval issues one opaque per-endpoint credential, and Home owns active/expired/replaced/revoked state. Revocation blocks new activity, interrupts reachable work, rejects late actions without mutation, and requires fresh authorization; exact lifetimes, storage, and approval UI remain open in the foundation spec.
- (decision by user) Set the Home enrollment-code lifetime to five minutes. The code remains single-use and approval-gated; credential lifetime, rotation, storage, and approval UI remain open.
- (decision by user) Set the pilot endpoint credential policy to 90 days, automatic renewal in the final 14 days, and at most 10 minutes of old-credential overlap for a lost rotation response. Explicit revocation wins immediately; an expired device must re-enroll.
- (decision by user) Set credential renewal idempotency at the Home boundary: bind a client rotation request ID to the current credential generation, return the same replacement on retry during the 10-minute overlap, reject competing requests, and let revocation invalidate the retry path.
- (decision by user) Set the Home credential storage boundary: persist only keyed digests, keep the root secret outside SQLite, encrypt retryable replacement material for the 10-minute overlap, and require platform-secure endpoint storage or fail closed. Exact cryptographic primitive and store adapter remain implementation choices.
- (decision by user) Set the first Home pairing approval surface to the existing TUI: it uses the trusted Home admin boundary to review endpoint identity, confirmation code, expiry, requested scope, Room, and Profile mappings; approval is bounded and atomic with credential issuance, while phones later reuse the same contract.
- (decision) [ADOPTED] Extend Home ownership from the foundation to Profile mappings and conversation claims: household-wide phrase mappings are unique by Profile, aliases are explicit, per-device grants are visible and snapshot-based, and a device sends only an opaque mapping ID. Room-local arbitration remains the existing 250 ms monotonic window; Home binds the winner to the fixed Profile and Hermes Session, permits independent same-Profile Sessions in separate Rooms, and closes only on the bounded idle and explicit-close rules from the Slice B specification.
- (decision) [ADOPTED] Keep the Home bridge on the ordinary Hermes session protocol. After a valid claim, Home opens an ordinary server-side Hermes Session with a server-held token and returns only ready or unavailable plus an opaque conversation handle. Endpoints receive existing JSON, PCM, timing, and structured-prompt events; no new Hermes channel, endpoint fallback, automatic retry, promotion, or replay of uncertain turns is introduced.
- (decision) [ADOPTED] Make endpoint permissions additive, per-device, and revocable. Conversation, Watch, notification categories, sensitive replacement, choices, and artifact proposal or Apply are separate grants; Home checks them before forwarding actions. Revocation stops new work and observation, interrupts reachable active work, and rejects late actions. Sensitive entry remains masked and replacement-only; Home transports artifact authorization and status without owning file contents.
- (decision) [ADOPTED] Keep Watch and notifications on separate redacted, ephemeral Home fan-out. Watch gets one bounded Safe Preview followed by transcript and status for the current task or session only, with no microphone, audio, prompt, interrupt, or control authority. Notifications are category-scoped, per-device, quiet-hours and privacy aware, shared-display safe, stale-expiring, and never create or interrupt a hidden conversation.
- (decision) [ADOPTED] Establish a separate Household Diagnostics boundary for FR-51 through FR-53. Every successful, failed, interrupted, and unavailable turn emits a versioned content-safe event envelope with one correlation ID across endpoint, Home, and Hermes; automatic metrics and structured events exclude prompts, transcripts, audio, credentials, keys, sensitive values, and private notification content. Explicit incident capture is a separately authorized, previewable, encrypted bundle containing a bounded 60-second pre-failure ring buffer; metrics, logs, and bundles have independent retention, deletion and preservation, and outage behavior, and telemetry never blocks or replays a live turn.
- (decision) [ADOPTED] Keep Home as authorization and status transport for choices and artifacts, not the owner of assistant semantics or artifact bytes. Bounded choice actions remain structured, session, turn, object, and freshness bound, and explicit; artifact mutation remains proposal-first with a visible diff and Apply guarded by revision. Arbitrary files use a future upload or reference path and do not travel through the voice WebSocket.
- (event) Architecture pass for the next-wave PRD is now represented in the Home spine: Slice B is a load-bearing companion, the ordinary bridge, grants, observation and notification, Household Diagnostics, and choice and artifact boundaries are adopted. Exact log and encrypted-bundle backends, notification delivery mechanics, health vocabulary, native choice contract, and final artifact backends remain intentionally deferred to their owning specifications. No source code changed.
- (decision) [ADOPTED] Treat health as a separate, on-demand, single-device read-only diagnostic path within the Home boundary. It reports the failing boundary—pairing, credential, route, Hermes Session, microphone, speaker, or display—and a safe next action where known; it never exposes bearer credentials, wakes or records merely to prove health, turns a cached green result into a live-session claim, or expands into a fleet dashboard.
- (decision) [ADOPTED] Set the Household Diagnostics retention targets in the Home contract: safe metrics retain for 30 days, detailed structured events for 14 days, and explicit incident bundles for 7 days unless an authorized person preserves them. Retention, preservation, deletion, and audit remain separate from live Session state and must continue to fail open for the conversation when the collector or store is unavailable.
- (event) Reviewer gate passed after adding the missing single-device health rule and explicit 30-day metrics, 14-day detailed-event, and 7-day incident-bundle retention targets. Home spine lint is clean; status is final at architecture altitude. Slice C and Slice D detailed specifications remain the next delivery gates. No source code changed.
- (decision) [ADOPTED] The Home bridge is also the transport boundary for response timing: it preserves the ordinary Hermes timing metadata alongside JSON, PCM, and structured prompts, while each endpoint aligns visible text to audio actually played. Home does not create a second timing or answer channel; any timing sidecar remains an adapter fallback.

- (event) Slice D formal specification is now a load-bearing companion of the Home architecture and is linked from the next-feature slate; its six capabilities preserve safe automatic lifecycle telemetry, separate review stores, explicit previewed incident capture, fixed retention, audit/deletion, and no-blocking behavior.
