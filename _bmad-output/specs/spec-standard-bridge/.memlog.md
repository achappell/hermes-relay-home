- (direction by user) Create a focused Story 2 spec so implementation and code review have explicit acceptance context.
- (decision by coach) Scope this spec to the framework-independent Home-to-Standard-Hermes bridge seam; adopt the existing migration, route-roaming, architecture, and project-context artifacts as companions; do not create stories.yaml.
- (capability by coach) CAP-1: Authorized Home callers can open or resume a Standard Hermes conversation while retaining the correct Profile and session identity.
- (capability by coach) CAP-2: Home can submit a non-empty prompt and expose ordered, correlated Standard text updates with cumulative previews and an explicit terminal state.
- (capability by coach) CAP-3: Home can deliver response audio alongside text without corrupting or duplicating PCM frames or making text depend on optional audio.
- (capability by coach) CAP-4: Home can interrupt a live turn, answer structured prompts, and expose and dispatch advertised commands with honest outcomes.
- (capability by coach) CAP-5: Home can recover a lost Standard connection and resume the existing conversation without replaying prior input or binding to a different Profile or session.
- (constraint by coach) The compatibility target is Standard Hermes 0.21.1 at the documented /api/ws and /api/audio/speak-stream boundaries; the fork-only /voice-session path is not a target.
- (constraint by coach) Home owns endpoint authorization and keeps the Hermes bearer credential server-side; credentials must not enter endpoint payloads, URLs, logs, snapshots, prompts, transcripts, audio, or diagnostics.
- (constraint by coach) The bridge remains framework-independent and must be testable through fake ports and deterministic fixtures without a live Hermes endpoint or physical hardware.
- (constraint by coach) One reader demultiplexes RPC responses from gateway events, writes are serialized, and every wait has a finite bound with ping used for liveness decisions.
- (constraint by coach) Standard event identity, meaning, ordering, cumulative text-preview semantics, append-only audio-suffix semantics, and signed-16 little-endian PCM metadata must be preserved.
- (constraint by coach) Profile and session mismatches fail closed, conversation handles remain opaque to endpoint callers, and unsupported optional capabilities are reported rather than guessed.
- (constraint by coach) Reconnect resumes an existing session without replaying prompts or switching transport paths automatically; interrupted turns reach an honest terminal state.
- (constraint by coach) A response-audio sidecar may fail independently; text remains usable and the audio failure is typed and observable.
- (constraint by coach) The final Home route envelope and roaming identity proof are defined elsewhere and must not be invented by this bridge slice.
- (non-goal by coach) Define the final versioned Home endpoint WebSocket or HTTP route envelope, route path, or roaming identity proof.
- (non-goal by coach) Implement live Hermes deployment validation, physical hardware adapters, client integrations, production framework wiring, persistence, or pairing.
- (non-goal by coach) Add timing or latency authority that Standard Hermes does not explicitly provide.
- (non-goal by coach) Create a second conversation authority or change Hermes session and answer ownership beyond the adapter seam.
- (non-goal by coach) Replay a pending prompt or switch transport paths automatically after reconnect.
- (success by coach) Success is a deterministic fake-gateway and fake-audio suite that proves authorized session create and resume, ordered text, separate PCM audio, interruption, structured prompts, advertised commands, bounded reconnect, no replay, typed failures, and credential isolation at the Home boundary.
- (assumption by coach) The existing Home authorization and ConversationGrant seam supplies authorization while the exact public endpoint envelope remains deferred to route roaming.
- (assumption by coach) The existing Standard Hermes 0.21.1 baseline and migration artifacts are the accepted compatibility authority for this slice.
- (assumption by coach) Unit-level deterministic fixtures are sufficient for this slice; live Hermes and hardware validation are later gates.
- (question by coach) What final Home route envelope and roaming identity proof will consume this bridge seam?
- (question by coach) Which live Standard Hermes smoke test, if any, becomes a release gate after deterministic compatibility passes?
- (question by coach) Should the bridge be integrated into the existing SessionProtocol in the route slice, or remain a framework-independent seam?
