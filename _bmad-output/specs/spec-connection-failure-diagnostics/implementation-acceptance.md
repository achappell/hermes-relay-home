## Narrow approval gates and rollout

1. **Home + proxy owners:** approve optional handshake header and socket-factory contract; verify configured proxy termination and no forwarding to Standard. No upstream agent approval/patch is presumed.
2. **Home + iOS owners:** approve optional capability/request/result metadata and schema-2 report field/enumeration changes, including both success and rejection. Shared contract approval must be explicitly recorded before cross-repo implementation; this document is a proposal, not that record.
3. **Privacy + deployment owner:** approve proposed quota/drop/drain defaults and restricted local access. Canonical 14-day detailed events and existing 7-day opted-in client-report policies remain fixed unless owning authority separately changes them.

Server-first: keep schema-1 intake and legacy RPC behavior; enable schema-2 support/capability only after strict compatibility tests. Old client + new Home, new client + old Home, new Home + old proxy and old Home + new proxy must operate unchanged; absent negotiation yields missing correlation, not rejection or fabricated joins. Deploy independently with exact tested provenance, then enable approved additions. Rollback disables additions/restores a verified compatible build without changing mode, replaying turns, leaking metadata to Standard or invalidating old retained reports. Reader handles each retained schema by its version; unknown schema is safely unavailable, not coerced. Current Swift envelope and nested capability decoders are strict: only an upgraded client sends the proposed handshake opt-in header, and Home never emits new fields to legacy clients. Background upload without established support uses the safe schema-1 projection described in the event contract. No new report receipt acknowledgement RPC is needed: client-local receive/resolve events uploaded under existing consent provide evidence.
